# Handoff: T19-live-palette
Cause: `HeaderSection.kt` built `medallion(planet)` and `dayRule(planet)` (planet medallion and the divider, colours baked into the parts) inside `remember(planet)`. The key did not include the palette, so they kept the old colours until the screen was rebuilt (rotation).
Fix: both remembers are now keyed `remember(planet, Medieval.palette)` (2 lines, HeaderSection.kt).
Audit of the other medieval files (greps for remember, lazy, cached Brush/Path/bitmap, top-level val): the rest already follow live: top-level colour vals are getters (`get() = Medieval.X`), CapFill is a getter, WeatherScene parts are keyed on the palette, OrbGlass reads the palette orb pictures each composition, remaining `remember {}` hold only fonts, random grains, system services, app data. No other change needed.
Proof: new `app/ui/src/test/.../T19Shots.kt`. Home is composed once in Gold, the palette is switched in the same composition (no activity recreate), re-rendered; then a second Home is composed fresh in the new palette as reference and the top 28% (header) is compared pixel by pixel. Without the fix: 1.3-1.9% of header pixels differ (Royal, Bone, Verdigris; Ember 0.4%). With the fix: 0.1% (only animation). Pictures in `docs/design/shots/T19/` (gold-before-X, gold-to-X, started-in-X for royal, ember, bone, verdigris); I looked at royal, ember, bone: every header element changed, no gold left.
Not verified: on the phone (only Robolectric). Run: `./gradlew :app:ui:testDebugUnitTest --tests "*T19Shots*" --offline`.
